项目 campus-runner-miniapp · 工作目录 D:\runner · 2026-09-17
根因 你截图里的两条红字报错，其实是同一个根因的连锁反应。

合并提交 5d6ae07 时留下了未解决的 Git 冲突标记，导致 4 个页面 JS 文件语法错误。 微信开发者工具的模块加载器 require 到编译失败的模块，于是报「module 未定义」； 页面组件构造失败后被降级成占位组件，于是接着报 wx://not-found。

冲突标记残留  →  4 个 JS 语法错误  →  module is not defined
                                      ↳ wx://not-found  →  页面白屏
                                      ↳ 清理后恢复

一、阻塞级问题（已修复）

1. 4 个文件的 Git 冲突标记

文件冲突位置处理

pages/mine/mine.js第 48 行保留含分享方法的分支

pages/taskDetail/taskDetail.js第 281 行保留 cancelOrder 分支
取舍依据 旧分支是复制粘贴残留 —— handleCancel（取消订单）里调用的是 api.acceptTask（接单）， 属于明显错误，已丢弃。冲突解决后还逐个核对了尾部括号是否被标记切开。

2. order.js 调用了不存在的方法（订单页永久空白）

pages/order/order.js 的 onLoad 调用 this.getUserLocation()， 但文件里根本没有定义这个方法 → 抛 TypeError。更严重的是执行被中断， 后面的首次数据加载从未执行，onShow 又写成 if (initialized) load()， 首次进入时 initialized 为 false，两边都不加载 —— 订单页永远空白。

✔ 已补上 getUserLocation()，并用 .finally() 串联首次加载（定位失败也不阻断）。

3. taskDetail.js 方法重复定义 + 调用不存在的 API

pages/taskDetail/taskDetail.js 中 handleCancel 被定义了 3 次， 前两次调用的是 api.cancelTask —— 而 utils/api.js 只导出了 cancelOrder， cancelTask 并不存在。三个同名方法后者覆盖前者，逻辑隐晦且脆弱。

✔ 已合并为单一定义，统一调用 api.cancelOrder。

二、功能补全（已改进）

体验publish.js 资料状态不刷新，导致无法发单

用户先进入「发布」页（资料未完善）→ 去「个人资料」补全 → 返回发布页， profileState 仍是旧值，validateForm 一直拦住不让发单。 已新增 onShow 静默刷新 —— 且只刷新资料状态、不重置表单，避免用户切 tab 回来正在填写的内容被清空。

体验taskDetail 加载失败即整页白屏

原来整个页面包在 wx:if="{{task.id}}" 里，没有任何 else 分支。 任务加载失败、链接参数丢失时就是一片空白。已补上加载态与空态/错误态引导， 并把「取消订单」按钮从「有接单人就显示」改为受 task.canCancel 权限位约束。

体验auth.js 取消授权就完全无法登录

原来 wx.getUserProfile 失败即中断整个登录流程。 实际上登录只依赖 openid，头像昵称可在「个人资料」页补充。 已改为降级登录：接口不可用或用户拒绝授权时，仍以 openid 完成登录。

数据admin 后台枚举值直接渲染英文

提现状态显示 pending、角色显示 admin、订单状态显示 accepted / paid。 已统一中文化（审核中 / 管理员 / 待送达 / 已支付），并补上 totalRunnerIncomeText 默认值； 4 个列表全部补了空态；服务端 adminService 补返回 campusAreaText。

数据wallet 默认 data 缺字段

初始 wallet 对象没有 withdrawals 键，首屏取值异常； 提现记录也显示英文状态。已补默认空数组，并加入状态中文字典。

稳定性app.js 未读轮询后台空转

15 秒一次的轮询在 onLaunch 启动后永不停止，退到后台仍在跑； 且 onLaunch + onShow 可能造成多个并行定时器。 已加 onHide 停止 / onShow 恢复，并在启动前清理旧定时器。

一致性补齐分享能力与首页刷新

chat 页与聊天详情页补上 onShareAppMessage（详情页分享时携带会话 id）； 首页 onShow 由「什么都不做」改为静默刷新，保证待接任务数等汇总信息不过期。
